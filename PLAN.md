# Plan: JSA (Job Search Assistant)

## Goal
JSA is a CLI-launched local web application that automates tailored job-application document generation. Given a CSV of job listings and a CV, it runs a 2-stage AI pipeline (CV adjust → cover letter) per job, persists all state in SQLite for crash resilience, and presents a React GUI for async review, follow-up answering, and PDF approval — up to 5 jobs in parallel.

## Architecture reference
See ARCH.md — Python/FastAPI backend + React/Vite frontend; SQLite persistence; sentinel-based agent protocol; asyncio Semaphore(5) park-as-task-exit concurrency; Renderer ABC for PDF output.

## Constraints
- Python 3.11+. Use `async/await` throughout the backend; no blocking calls on the event loop (use `asyncio.to_thread` for sync libs).
- SQLAlchemy 2.0 style (mapped_column, Mapped[T], async engine). No raw SQL except for the two partial unique indexes (DDL-level).
- All job state transitions go through `state_machine.transition()` — never set `Job.state` directly.
- Every checkpoint (Message rows + Document row + Job state) is committed in a single DB transaction via `repo.checkpoint()`.
- All agent replies must go through `protocol.parse_reply()` before the stage logic acts on them.
- Fakes over mocks in tests: use `FakeAgentBackend` and `FakeRenderer`, not `unittest.mock.patch` on internals.
- React frontend: TypeScript strict mode. No `any`. Zustand for state — no Redux, no Context for global state.
- WeasyPrint runs only post-approval — never speculatively.
- Port default: 8765. Configurable via `--port` / env var.
- macOS + Linux only. Windows not targeted (WeasyPrint system deps).

## Open questions
- Should `jsa` auto-exit when all jobs reach terminal states (approved/failed), or always run until Ctrl-C? → Defaulting to Ctrl-C for v1.
- Tier C "skip altogether" mode (run no stages, just mark done) → deferred to v1.1.
- Gemini CLI native resume mechanism: verify empirically in Phase 5; fall back to prompt-determinism if absent.
- Multiple CVs per run (one CV per job row) → not in v1 scope; schema already supports it.
